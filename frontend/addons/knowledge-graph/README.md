# Knowledge graph add-on

The page, API client, session cache, worker and 3d-force-graph adapter live here. The host route only mounts the add-on. Navigation comes from `addons/registry.ts`; the authenticated Node search gateway and Python query service have corresponding add-on registries. This is a bundled add-on, not a runtime plugin marketplace. Removing its three registry entries disables its navigation and API registration; remove the host route as well when uninstalling the bundle.

The API uses the existing identity, semantic scopes and readable-record listing. It never accepts a caller-supplied user or organization. Connections only include readable endpoints. Source-limited connected-app tokens cannot export the overview.

The browser reuses a completed graph and XYZ layout for five minutes without fetching. Recently stale snapshots remain available for up to 30 minutes on reload while an authenticated export checks for updates in the background. Manual Refresh also keeps the current view visible. Unchanged graph data renews the snapshot without running the layout worker or resetting the camera. Changed data swaps only after layout completes. Refresh errors retain the last good view with an inline warning. Snapshot scope includes API origin, account, organization and a tab-session nonce; no token is saved. Logout clears disk state even when the add-on was not loaded, and session reset aborts pending work and rejects late writes. Old/malformed entries and unavailable storage fall back to a fresh export. Permission/source changes may remain visible in a saved snapshot until revalidation succeeds; record access remains server-authorized.

Louvain finds communities. A worker lays out both the weighted community graph and its members with a three-dimensional force simulation. These are topology-based coordinates, not document embedding distances. Small native sphere dots are used throughout, without halos or text sprites. The overview samples up to 24 members per cluster and retains compact count-bearing cluster markers and aggregate links. Clicking a cluster animates the camera to its existing location while retaining surrounding context. Camera proximity reveals 240, 1,200, then at most 6,000 focused members; the caption reports the actual rendered record/entity count against the full readable graph. Zooming back out collapses detail. Record selection reveals its complete immediate neighborhood. Every stored connection between rendered endpoints is drawn, including in dense clusters. Fixed-coordinate connections share one Three.js LineSegments draw call, rather than dropping edges or allocating one object per link. Search reaches every readable node, including those omitted at the current zoom level.

Drag rotates, right-drag pans, and scroll zooms. Orbit controls support one-finger rotation and two-finger zoom/pan. Buttons provide rotation, zoom and reset without dragging. Camera transitions respect reduced-motion preferences. The MIT-licensed 3d-force-graph library owns node rendering, orbit controls, ray picking and hover labels. Fixed worker coordinates disable its second simulation. Its normal render loop remains active while mounted; the library destructor releases it when leaving the page. A lost graphics context offers a renderer-only retry.

Run `vitest run addons/knowledge-graph/__tests__`, TypeScript and the i18n checks. Verify a static export because production serves the exported Next.js UI through Express. Browser checks should cover a dense synthetic graph, narrow portrait and landscape viewports, rotation, cluster selection, record search and reset. Real-device GPU/touch behavior still needs hardware testing.

Unknown totals use the standard loader without a progress bar or a zero-of-zero label. Determinate progress starts only after a real record count is available. Cached/background refreshes use an inline status and keep the graph visible.
