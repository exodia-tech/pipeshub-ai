# Marco maintenance reporting pilot

`agent.json` and `system-prompt.md` are a private, human-owned draft identity. They attach no source, tool, account or schedule. The account needs an explicit, scoped project authorization before it can process client information. A service identity is preferable for durable unattended work only when the shared native scheduler provides explicit source grants, active identity checks, audit attribution and tested ACL enforcement. Do not bypass existing public-only scheduler restrictions.

`report.py` is an **offline evidence-preparation prototype**, not a connected agent or a Google Doc writer. It accepts structured, already-authorized source records, preserves their explicit stage and citations, refuses cross-agreement records, deduplicates source revisions as of the review time and reports unavailable/partial time as unknown. Time records require start/end instants and recorded seconds; an entry crossing a report boundary requires manual reconciliation instead of assigning its whole duration to one period. Adapters must retrieve overlapping intervals, not only those starting in the window. `report_window` requires a confirmed local anchor and timezone; local calendar windows remain correct across DST. `report_key` is a stable client-agreement/window identifier, not a persistent ledger.

Hubstaff's [project activity API](https://developer.hubstaff.com/reference/activities/) offers project-scoped detailed time blocks with an exclusive stop time, pagination and a seven-day maximum per request; a two-week report needs multiple complete reads. Its daily aggregates use the organization timezone and an inclusive stop date, so they are not interchangeable with arbitrary instant-based report windows. The API notes data latency and update-retention limits. These are API capabilities only; account access, the project mapping and actual coverage are not verified.

Run `python -m unittest discover -s deployment/agency-agents/marco -p 'test_*.py'` from the repository root. Fixtures are synthetic; the example domains cannot receive traffic. Nothing in this prototype fetches sources, creates documents, configures a schedule, sends messages or stores credentials.

Before a live pilot, the shared runtime must supply scoped, authenticated source adapters; reliable persistent per-agreement/per-window reservation and reconciliation on ambiguous creation; a human-edit-preserving document workflow; client-specific storage/sharing and draft-only mail permissions; and audit/usage records. A late entry must be surfaced for human reconciliation, never silently overwrite an existing document. A static hash alone is not a concurrency lock or proof that a document exists. Confirm the signed agreement, period anchor, owner, destination folder, audience and authorized Slack channel before activation. Source availability and approvals vary by agreement.
