Hubstaff's public API documents project activities and project membership. Use a scoped read-only identity, preserve project/member restrictions and do not fetch keyboard/mouse activity, screenshots or unrelated projects. A project viewer can read project reports without changing project settings, subject to actual organization policy and API entitlements. Hubstaff's `hubstaff:read` scope covers the V2 API broadly for everything the identity can see; it is not restricted to an individual endpoint. Hubstaff is not an accounting ledger: an approved accounting system or maintained finance sheet must supply invoice type, due date and authoritative payment status. Relevant official references: https://developer.hubstaff.com/authentication/, https://developer.hubstaff.com/reference/activities/, https://developer.hubstaff.com/reference/timesheets/ and https://developer.hubstaff.com/reference/members/. The current EXODIA Brain code search did not find a Hubstaff connector; live access has not been verified.

The current Brain usage ledger records agent and connector IDs and costs in nano-USD, but has no `project_id` field. An agent-to-project allocation must be independently documented and checked for exclusive attribution before project totals include those events. Shared or unknown usage remains unattributed. A EUR project also needs an approved dated conversion rate and auditable conversion policy before USD usage is added; the prototype does not perform FX. Completion model/cost mapping for Elio was previously unpriced (EXO-678); recheck actual data rather than treating missing pricing as zero.

`app.agents.finance_budget` is a pure, unconnected calculation prototype for authorized, normalized snapshots. It is not a scheduler, connector, permission check, dashboard or financial ledger. The calling boundary must enforce project/finance ACLs, source freshness and evidence links. IDs must be stable and unique within each source collection and revisions monotonically increase when an entry changes. Snapshot `captured_on` must equal the local reporting date. Period start is inclusive and end exclusive. Every budget/rate/AI/other cost must explicitly match the report currency; there is no FX conversion. Cost rates have non-overlapping effective intervals `[from, to)`. `other_costs` are confirmed project costs outside labour and AI, never invoice payments duplicating recognized costs. Set `time_complete`, `ai_complete`, `other_complete` and `no_overlap_verified` to true only after verifying source coverage, attribution, pagination and cross-source reconciliation for the selected project and period. Empty arrays alone do not prove zero activity. Unknown, unapproved or estimated costs prevent a final total, remaining budget or forecast; estimated AI charges are shown separately. A known cost is a lower bound only after overlap is reconciled, and 70/85/100 alerts are candidates based on that bound. Alert persistence, deduplication and acknowledgement require the shared runtime.

Invoice rows use the same ID/revision rule plus `project_id`, `kind` (`receivable` or `obligation`), `status` (`open`, `paid`, `void` or unknown), `due_date` and source link. Only explicit open status can be classified overdue or due soon; unknown or incomplete open rows are counted separately. This module does not confirm accounting reconciliation, negative adjustments, refunds, project attribution, currency minor-unit display or production access. Review the first real project against its budget, approved time, prices and finance ledger before enabling any output. Money remains `Decimal`; downstream presentation must use the currency's own minor-unit rounding rules.
